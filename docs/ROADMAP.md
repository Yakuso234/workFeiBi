# workFeiBi 更新计划

规划日期：2026-10-02。目标是把菲比啾比和弗糯糯做成有不同反应、能长期陪伴学习的桌宠，同时让计时提醒保持可靠。以下区分本轮实施范围与后续计划；计划不代表已实现，实际验证结果以 `QA.md`、项目进度和对应提交为准。

## 参考了哪些桌宠

| 官方项目 | 已核对的特点 | workFeiBi 的取舍 |
| --- | --- | --- |
| [VPet](https://github.com/LorisYounger/VPet) | 投喂、摸头、提起等交互；动作有不同状态；支持扩展动画、物品和主题。代码采用 Apache-2.0，动画另有条款。 | 借鉴“动作由状态驱动”和角色资源包组织方式；自行实现陪伴数值与动画调度。角色图片、声音不能由代码许可证推定可用。 |
| [VS Code Pets](https://github.com/tonybaloney/vscode-pets) | 多宠物、背景选择、抛球玩法；代码采用 MIT，README 单独列出素材作者。 | 先做轻量互动和动作预览，后续再做追球与双角色交流。编辑器内玩法需重新设计为不遮挡工作的桌面玩法。 |
| [Shijima-Qt](https://github.com/pixelomer/Shijima-Qt) | 跨平台桌宠、窗口跟踪；代码采用 GPL-3.0。官方仓库现已归档，作者说明维护困难。 | 借鉴屏幕边缘与窗口附着的交互思路，先在 Windows 做可关闭的活动区域；不把已归档程序接为运行依赖。 |

本轮只参考公开功能设计，没有导入上述项目的代码、人物或音频。既有菲比赛博风外观继续保留；新增人物要先把同一套动作系统跑通，再补资产。用户许可本地使用的糯糯短音频继续留在本机，公开仓库构建需要有清楚的缺失回退。

### 1.2：先让现有两个角色变得有反应

下面的验收条目包含完整目标，不代表每个设备场景都已覆盖；本轮实际验证范围见 `QA.md`。多屏、系统级鼠标与实际听音仍未人工验收。声音预览在学习安静模式中也会静音，可暂停计时或关闭该模式后试听。当前两个角色共用成长进度，分角色成长留到双宠阶段迁移。

1. **有节奏的待机。** 用洗牌动作池轮换动作，池内尽量不重复，跨池避免紧接着同一个动作；不同学习阶段使用不同池。提供安静、标准、活泼频率。提醒、拖动、主动互动优先，不能被随机动作切断。专注安静模式在学习计时运行期间减少主动表演；减少动态模式降低位移和闪烁。验收：固定随机输入可以复现序列；连续轮换有多样性；关闭后不再安排新待机；再次开启能恢复。

2. **摸头和睡觉各有反应。** 摸头用开心/爱心反馈；喂食用点心反馈；伸展有伸展节奏；打盹进入更长的困倦姿势与睡眠反馈；转身使用对应角色的背面图。眼部、手脚动画不足处须如实标为姿势切换与程序动效，不能把全图平移称作肢体逐帧动画。验收：两名角色逐项点按，动作、反馈与持续时间能区分；连点受到冷却约束；不会启动、跳过或重置倒计时。

3. **轻量陪伴成长。** 保存心情、精力、亲密度和互动次数；摸头、喂食、休息、完成整轮专注分别有明确数值效果，值始终限于合理范围。离线期间不掉亲密度，不以生病或惩罚催促打开软件；超时生气属于当前提醒状态。验收：重启保留进度；旧配置自动得到默认值；完整专注只奖励一次；预览动作不刷成长。

4. **动作实验室。** 控制台列出眨眼、挥手、抬脚、伸展、摇头、打盹、转身、生气敲屏等预览按钮，让用户直接检查效果。预览共用正式动作路径，到期提醒优先且不能被预览覆盖。验收：切换角色后按钮作用于新角色；预览不改计时阶段、不记入专注统计、不消耗或奖励数值。

5. **可见且可关闭的敲屏。** 生气时在桌宠附近绘制分叉裂纹和短时冲击，用透明、鼠标穿透窗口显示。等页面加载完成再播放，播放后自动隐藏；确认提醒、关特效或开启减少动态立即收起。验收：直接预览能观察裂纹；渲染像素确实非空；冷启动首次触发、连续触发、多屏位置和自动隐藏都验证；下面的桌面仍可操作。裂纹只是一层临时视觉效果。

6. **声音与来源可解释。** 优先用户本地导入，其次可用的本地糯糯短片段，再回退本机语音/提示音；播放失败也能继续回退。菲比普通提示保持较高、稚气的音调，生气使用指定短句；糯糯以两个字为核心，依状态变化节奏。全局静音、零音量和确认提醒都应停止未完成播放。验收覆盖缺文件、坏文件、切角色和异步语音失败；实际可爱程度仍需本机试听，不能由解码成功代替听感验收。

### 1.3：真实动画与角色资源包

先为每名角色做一套统一比例的动作样板：呼吸 4–6 帧、眨眼 3–4 帧、挥手 6–8 帧、走路 6–8 帧、困倦 4–6 帧、生气蓄力/敲击/收手 6–10 帧。帧数是制作起点，不是已生成资产。可在连续位姿可控时改用分层骨骼，但先保留现有静态图作为加载失败回退。

资源清单包含角色名、版本、来源、许可说明、画布尺寸、脚底锚点、动作帧/时长/循环规则、命中区域、正背面关系、音效映射。图片先统一脚底和头部位置，避免切图时身高突然变化；服装正背面人工对照，不用水平翻转伪造后视。

验收必须包括逐帧接触表和连续播放：眼睛轮廓一致、肢体确实移动、背景透明、帧间无明显闪边、正背面衣饰合理。每一动作有进入、循环、退出过程；被提醒中断后可安全回到静止。主要风险是资产质量与制作时间，因此先完成两名角色的眨眼和挥手，再扩充全套。

2026-10-02 调整：提前以原创“发条鸮”做代码原生关节动画试点。它有独立头部、眼皮、翅膀和脚，复用现有动作调度、音效设置和提醒优先级，不引入第三方位图或人物素材。集中角色清单先统一 ID/名称/校验，尚不是开放的外部角色包加载器。看书/收书仍是后续构想。此试点不替代菲比和糯糯的连续帧制作。

### 1.4 已交付与活动区域后续

2026-10-03 根据用户自由扩展授权，先交付初音 40 张原始连续帧、四角色收藏快速出场、发条鸮三套配色/两款头饰，以及 45 秒接星星街机。资产许可与角色条件分开记录；初音无背面轨即不提供转身。小游戏状态在主进程，离页、提醒、换角色与恢复学习会取消，不把小游戏计入学习统计。源码和独立版均通过集成验证，形象/听感人工边界保留。

以下散步、追球与屏幕附着仍是后续计划，不因版本号到 1.4 就标记实现：

新增默认关闭的自由散步：用户选择当前屏幕底部或一个限定区域，桌宠按短距离路线行走、停下观察、回到休息点。拖动立即接管，结束拖动后重新选择安全落点；显示器断开、缩放变化或越界时移回可见工作区。

在休息阶段提供一次性抛球玩法：用户主动开始，角色追逐并把球送回，最多运行一小段时间，随时退出；学习倒计时到期立即让提醒接管。窗口攀爬作为后续实验开关，先验证坐标与系统兼容性再开放。

验收覆盖 100%/125%/150% 缩放、负坐标副屏、任务栏位置变化，以及关闭自由行走后的立即停止；球和角色不抢焦点，不自动移动鼠标，不拖走其他应用窗口。依赖真实走路动画和多屏坐标归一，不能仅靠加快整图移动交付。

### 1.5：双宠与学习纪念

可选同时显示菲比和糯糯：一方招手，另一方回应；共享学习倒计时但各自保留陪伴进度。只允许有限的同屏数量和低频互动，避免互相遮挡、声音重叠和性能上涨。进入提醒时统一调度，只播放一次主要提醒。

学习记录增加“完成本周目标”“累计专注里程碑”等非竞争纪念，以及本地 CSV/JSON 导出、配置与成长备份。纪念只由真实完成记录产生，跳过或预览不能累计；导出默认不包含音频和用户电脑路径。云同步、在线聊天、排行榜不在当前计划内。

本地 CSV/JSON 记录导出已提前列入本轮 1.3 第一阶段；它只提供记录/任务/共享成长档案，不是全量配置备份，也没有一键恢复。双宠、分角色成长迁移和导入恢复仍需后续设计。

## 每次完成前的核对

- 动手前列出本轮待办和验收条件，保留用户已确认的范围；新问题按影响排序，不反复要求确认已有授权。
- 验证有区别的动作、学习/休息提醒与确认、声音停止/回退、拖动与透明穿透；视觉效果必须看实际渲染，不能只检查文件存在。
- 记录自动验证和人工观察各自覆盖的内容，未验证项目保持待办，不把计划写成成果。
- 更新项目进度、验证记录与本计划的状态；仅清理本轮明确无用的缓存和旧构建，保留本地授权音频。
- 检查暂存文件，提交源码与必要素材；排除依赖、配置、缓存、独立构建和本地音频。推送后核对远端提交是否一致，网络失败须明确说明本地与远端状态。
